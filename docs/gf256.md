# Phép toán trong GF(256)

Tài liệu này mô tả các phép toán dùng cho lõi Reed–Solomon theo
[README](../README_RS_DE10_Lite.md), mục 2.1, và cấu hình hiện tại trong
[`rs_params.vh`](../rtl/include/rs_params.vh). Các ví dụ áp dụng cho đa thức
trường `0x11D` và phần tử nguyên thủy `0x02` đã chọn trong header.
README ban đầu chỉ chốt `m = 8`; các giá trị còn lại là mặc định của dự án.

## 1. Biểu diễn một symbol

GF(256) có 256 phần tử, mỗi phần tử được biểu diễn bằng một byte. Với byte
`a[7:0]`, bit `a[i]` là hệ số của `u^i` trong đa thức nhị phân:

```text
a(u) = a[7]*u^7 + a[6]*u^6 + ... + a[1]*u + a[0]
```

Ví dụ:

| Byte | Nhị phân | Đa thức đại diện |
| --- | --- | --- |
| `0x00` | `0000_0000` | `0` |
| `0x01` | `0000_0001` | `1` |
| `0x02` | `0000_0010` | `u` |
| `0x80` | `1000_0000` | `u^7` |
| `0xA7` | `1010_0111` | `u^7 + u^5 + u^2 + u + 1` |

`u` biểu diễn các bit bên trong một symbol. Biến `x` trong đa thức RS biểu
diễn vị trí các symbol của cả khối. Ví dụ, hệ số của `x^2` có thể là một byte
GF(256), bản thân byte đó lại được biểu diễn bằng đa thức theo `u`.

## 2. Đa thức trường và phần tử nguyên thủy

| Tham số trong header | Giá trị | Ý nghĩa |
| --- | --- | --- |
| `RS_M` | `8` | Số bit mỗi symbol |
| `GF_SIZE` | `256` | Số phần tử của trường |
| `GF_ORDER` | `255` | Số phần tử khác 0 |
| `GF_PRIM_POLY` | `9'h11D` | Đa thức trường đầy đủ, gồm hệ số bậc 8 |
| `GF_ALPHA` | `8'h02` | Phần tử nguyên thủy `alpha = u` |

Đa thức trường được chọn là:

```text
p(u) = u^8 + u^4 + u^3 + u^2 + 1
0x11D = 1_0001_1101 (nhị phân) = 285 (thập phân)
```

Đây cũng là đa thức mặc định cho `m = 8` trong bảng
[MathWorks — gf](https://www.mathworks.com/help/comm/ref/gf.html).

Rút gọn theo `p(u)` cho quan hệ:

```text
u^8 = u^4 + u^3 + u^2 + 1    trong trường đã chọn
```

Vì vậy, khi bit bậc 8 đã bị loại sau phép dịch byte, phần XOR rút gọn còn lại
là `0x1D`. Cần phân biệt `0x11D` là đa thức đầy đủ 9 bit với `0x1D` là phần
thấp 8 bit dùng trong phép dịch có rút gọn.

Với cấu hình này, các lũy thừa `alpha^0` đến `alpha^254` đi qua đủ 255 byte
khác 0 và `alpha^255 = 1`. Số 0 không nằm trong chu trình lũy thừa đó.

## 3. Cộng và trừ

Các hệ số thuộc GF(2), nên cộng và trừ đều là XOR từng bit, không có nhớ:

```text
a + b = a - b = a XOR b
```

Ví dụ:

```text
0x57 + 0x83 = 0xD4
0x57 - 0x83 = 0xD4
0xA7 + 0xA7 = 0x00
```

RTL có thể viết trực tiếp:

```verilog
assign sum = a ^ b;
```

Không dùng toán tử cộng/trừ số nguyên `+`, `-` để thay thế phép cộng/trừ hai
symbol GF(256). Việc cộng chỉ số, địa chỉ hoặc số mũ vẫn là số học nguyên.

## 4. Nhân và rút gọn

Nhân hai phần tử gồm hai bước: nhân các đa thức nhị phân bằng AND/XOR, sau
đó lấy phần dư đa thức khi chia cho `p(u)`. Tích trước rút gọn có bậc tối đa
14, cần tối đa 15 bit; kết quả sau rút gọn là một byte.

### 4.1. Nhân với alpha = 0x02

Gọi phép nhân với `alpha` là `xtime(a)`. Với đầu vào một byte:

```text
Nếu bit 7 ban đầu bằng 0: xtime(a) = (a << 1) AND 0xFF
Nếu bit 7 ban đầu bằng 1: xtime(a) = ((a << 1) AND 0xFF) XOR 0x1D
```

Phải kiểm tra bit 7 trước khi dịch. Ví dụ, `0x80` biểu diễn `u^7`; nhân với
`u` được `u^8`, rút gọn thành `0x1D`.

### 4.2. Thuật toán dịch và XOR

Xét lần lượt 8 bit của toán hạng `b`. Nếu bit đang xét bằng 1, XOR lũy thừa
tương ứng của `a` vào kết quả; mỗi bước cập nhật `a` bằng `xtime(a)`.
Mã Python dưới đây minh họa thuật toán cho cấu hình hiện tại:

```python
FIELD_POLY = 0x11D


def gf_mul(a, b):
    """Multiply two byte symbols using polynomial reduction."""
    if not (0 <= a <= 0xFF and 0 <= b <= 0xFF):
        raise ValueError("GF(256) symbols must be bytes")
    product = 0
    for _ in range(8):
        if b & 1:
            product ^= a
        carry = a & 0x80
        a = (a << 1) & 0xFF
        if carry:
            a ^= FIELD_POLY & 0xFF
        b >>= 1
    return product
```

Các kết quả tham chiếu của thuật toán, tất cả viết ở hệ hexadecimal:

| `a` | `b` | `gf_mul(a, b)` |
| --- | --- | --- |
| `0x00` | `0x57` | `0x00` |
| `0x01` | `0x57` | `0x57` |
| `0x80` | `0x02` | `0x1D` |
| `0xFF` | `0x02` | `0xE3` |
| `0x57` | `0x83` | `0x31` |
| `0x02` | `0x8E` | `0x01` |

Không thay phép nhân GF bằng `a * b`, `(a * b) % 256` hoặc phép `% 0x11D`
trên số nguyên. Phần dư cần tính là phần dư của phép chia đa thức nhị phân.

## 5. Lũy thừa, nghịch đảo và chia

Với `a != 0`, ta có `a^255 = 1`, nên `a^(-1) = a^254`. Nghịch đảo là phần
tử thỏa mãn `gf_mul(a, inverse(a)) = 0x01`. Đây là hệ quả của chu trình
nhân các phần tử khác 0; xem
[MathWorks — Galois Fields](https://www.mathworks.com/help/comm/ug/galois-fields.html).

Mã tham chiếu dưới đây dùng phép nhân ở mục 4:

```python
def gf_pow(a, exponent):
    """Use square-and-multiply for a byte and a nonnegative exponent."""
    if not (0 <= a <= 0xFF) or exponent < 0:
        raise ValueError("Invalid base or negative exponent")
    result = 1
    while exponent:
        if exponent & 1:
            result = gf_mul(result, a)
        a = gf_mul(a, a)
        exponent >>= 1
    return result


def gf_inv(a):
    if a == 0:
        raise ZeroDivisionError("Zero has no multiplicative inverse")
    return gf_pow(a, 254)


def gf_div(a, b):
    return gf_mul(a, gf_inv(b))
```

Ví dụ: `inverse(0x02) = 0x8E`, `0x57 / 0x57 = 0x01` và
`0x00 / 0x57 = 0x00`. Chia cho 0 luôn không xác định, kể cả `0 / 0`.
Hàm `gf_pow` quy ước số mũ 0 trả về 1, kể cả đầu vào 0; quy ước lập trình
này không làm cho 0 có nghịch đảo.

Module RTL nghịch đảo/chia cần quy định cách báo đầu vào không hợp lệ hoặc
để bộ điều khiển chặn thao tác đó. Không được sử dụng một byte trả về cho
`inverse(0)` như một kết quả toán học hợp lệ.

## 6. Bảng log và bảng lũy thừa

Có thể dùng ROM thay cho phép nhân dịch/XOR và phép tính nghịch đảo:

```text
exp[i] = alpha^i,                i = 0..254
log[exp[i]] = i,                 i = 0..254

a*b    = exp[(log[a] + log[b]) mod 255]       nếu a,b khác 0
inv(a) = exp[(-log[a]) mod 255]              nếu a khác 0
a/b    = exp[(log[a] - log[b]) mod 255]      nếu a,b khác 0
```

Phép cộng/trừ số mũ trong các công thức là số học nguyên modulo 255; không
phải XOR. Nếu tích có toán hạng 0 thì trả về 0 trước khi tra log.
Phép chia phải kiểm tra mẫu bằng 0 trước, sau đó mới xử lý tử bằng 0.
`log[0]` không có giá trị toán học hợp lệ.

Các giá trị đầu của bảng lũy thừa dùng để đối chiếu:

| Số mũ `i` | `alpha^i` |
| --- | --- |
| 0 | `0x01` |
| 1 | `0x02` |
| 2 | `0x04` |
| 3 | `0x08` |
| 4 | `0x10` |
| 5 | `0x20` |
| 6 | `0x40` |
| 7 | `0x80` |
| 8 | `0x1D` |
| 9 | `0x3A` |
| 10 | `0x74` |

Khi triển khai RTL, tổng hai log có thể đạt 508 nên cần ít nhất 9 bit.
Hiệu có thể âm; có thể dùng số có dấu đủ rộng hoặc tính
`log[a] + 255 - log[b]` bằng số học đủ rộng rồi rút gọn. Với địa chỉ modulo
255, miền địa chỉ chuẩn của `exp` chỉ là `0..254`.

## 7. Áp dụng vào encoder và decoder RS

Cấu hình hiện tại là mã rút ngắn RS(15,11) trên **GF(256)**. Độ dài 15
symbol không thay đổi kích thước trường thành GF(16).

- Encoder dùng XOR và nhân GF với các hệ số của đa thức sinh.
- Syndrome đánh giá đa thức nhận bằng phép nhân và cộng GF.
- Berlekamp–Massey dùng phép toán GF để cập nhật đa thức định vị lỗi.
- Chien search đánh giá đa thức định vị tại các điểm trong trường.
- Forney dùng nhân, nghịch đảo/chia để tính giá trị lỗi.
- Bộ sửa lỗi XOR giá trị lỗi vào symbol nhận.

Theo header, nghiệm đầu là `alpha^0`, bước số mũ là 1. Với bốn symbol
parity, các điểm tính syndrome là `0x01`, `0x02`, `0x04`, `0x08`.

Với thứ tự hệ số bậc cao trước, có thể đánh giá bằng Horner:

```text
acc = 0
Với từng symbol c[i], i từ 0 đến N-1:
    acc = gf_mul(acc, beta) XOR c[i]
Kết quả cuối là c(beta).
```

`p(u)` quy định phép nhân bên trong một symbol; `g(x)` là đa thức sinh RS
với hệ số thuộc GF(256). Không dùng hai đa thức này thay thế cho nhau.

## 8. Lựa chọn kiến trúc RTL

| Cách triển khai | Đặc điểm cần cân nhắc |
| --- | --- |
| Nhân dịch/XOR tổ hợp | Triển khai các bước thành logic tổ hợp; kiểm tra độ trễ đường dữ liệu |
| Nhân dịch/XOR tuần tự | Có thể dùng lại phần cứng qua 8 bước; cần điều khiển chu kỳ và bắt tay |
| Nhân hệ số cố định | Có thể rút gọn thành mạng XOR khi hệ số encoder đã biết |
| Bảng log/exp | Cần xử lý số 0, địa chỉ và độ trễ đọc ROM |
| ROM nghịch đảo | Tra trực tiếp theo byte; đầu vào 0 vẫn phải được xử lý riêng |

Vòng lặp 8 lần trong logic tổ hợp không tự tạo thành 8 chu kỳ clock.
Độ trễ, `valid/ready` và tài nguyên phải được xác định theo kiến trúc module
thực tế. Khi dùng ROM hoặc pipeline, bộ điều khiển phải tính cả độ trễ đó.

## 9. Kiểm chứng phép toán

Các tiêu chí cho model và testbench khi triển khai:

- Đối chiếu đủ `256 * 256 = 65.536` cặp đầu vào của multiplier với cách
  tính độc lập: tạo tích đa thức chưa rút gọn, rồi chia đa thức bằng XOR.
- Kiểm tra `a + a = 0`, `a + 0 = a`, `a*0 = 0`, `a*1 = a` cho mọi byte.
- Kiểm tra giao hoán và tính phân phối bằng các bộ dữ liệu đại diện.
- Với mọi `a` từ 1 đến 255, kiểm tra `a*inverse(a) = 1`.
- Kiểm tra `alpha` sinh đúng 255 giá trị khác 0 trước khi trở lại 1.
- Kiểm tra các ví dụ số trong tài liệu, đầu vào 0 của nghịch đảo và mẫu 0
  của phép chia; không coi hai trường hợp không hợp lệ là phép toán hợp lệ.
- Với RTL tuần tự, kiểm tra reset, độ trễ và bắt tay theo hợp đồng module.

Các đoạn Python trong tài liệu là mã minh họa. Tài liệu này không xác nhận
các module tại `rtl/gf_arithmetic/`, model tại `model/gf256_model.py` hoặc
các testbench tương ứng đã được triển khai. Khi thay đổi đa thức trường hay
`alpha`, phải cập nhật đồng bộ header, model, ROM và vector kiểm thử.
